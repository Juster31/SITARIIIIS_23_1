# Вариант 1. Текстовый редактор с историей изменений

Консольное приложение, реализующее текстовый редактор с поддержкой многоступенчатой отмены/повтора действий (undo/redo) и сохранения снимков состояния (чекпоинтов) с использованием паттернов проектирования **Command** и **Memento**.

![Диаграмма классов](diagramm_class.jpg)

**Основные компоненты:**

* **Patterns:** `ICommand` и его реализации (команды), `CommandManager` (Invoker), `HistoryCaretaker` (Caretaker).

## 3. Использованные паттерны и их обоснование

### 3.1. Command (Команда)
**Проблема:** Необходимо выполнять различные операции над документом (вставка, удаление, замена, форматирование) и иметь возможность отменять их (undo) и повторять (redo). Если реализовывать это через жесткий `switch/case` в одном методе, то добавление новой команды потребует изменения существующего кода, а логика отмены перемешается с логикой выполнения.

**Решение:** Каждая операция оформлена отдельным классом (`InsertLineCommand`, `DeleteLineCommand`, `ReplaceTextCommand`, `FormatLineCommand`), реализующим интерфейс `ICommand` с методами `Execute()` и `Undo()`. Команда сама знает, как себя выполнить и какие данные сохранить для отмены. Это позволяет легко добавлять новые типы операций, просто создавая новые классы, не меняя основной код.

### 3.2. Memento (Снимок)
**Проблема:** Приложению нужно сохранять «чекпоинты» (снимки) документа и возвращаться к ним позже. Если сделать поля документа публичными для копирования, любой внешний код сможет случайно сломать его состояние. Инкапсуляция нарушится.

**Решение:** Паттерн Memento позволяет сохранить внутреннее состояние объекта, не раскрывая его деталей. Класс `Document` (Originator) умеет создавать снимок `DocumentMemento` и восстанавливаться из него. Поля `DocumentMemento` помечены как `internal` — внешний код (например, демо-стенд) может хранить этот объект, но не может заглянуть внутрь или изменить его. Целостность данных гарантирована.

### 3.3. Invoker и Caretaker (Вызывающий и Опекун)
**Проблема:** Где-то нужно хранить историю команд для отмены/повтора и коллекцию сохраненных чекпоинтов. Если хранить их прямо в `Main`, то `Main` перестанет быть просто демо-стендом и превратится в свалку бизнес-логики.

**Решение:** 
* Класс `CommandManager` выступает в роли **Invoker**: он хранит два стека (`_undo` и `_redo`), управляет вызовами `Execute()` и `Undo()`, но абсолютно ничего не знает о внутреннем устройстве документа. 
* Класс `HistoryCaretaker` выступает в роли **Caretaker**: он хранит словарь снимков `DocumentMemento` по именам, не заглядывая в их содержимое. 
Это разделение позволяет держать бизнес-логику в классах, оставляя `Program.cs` чистым.
