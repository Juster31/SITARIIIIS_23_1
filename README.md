# Вариант 1. Текстовый редактор с историей изменений

Консольное приложение, реализующее текстовый редактор с поддержкой многоступенчатой отмены/повтора действий (undo/redo) и сохранения снимков состояния (чекпоинтов) с использованием паттернов проектирования **Command** и **Memento**.

## 2. Диаграмма классов

Архитектура решения разделена на доменную модель (`Models`) и паттерны проектирования (`Patterns`).

![Диаграмма классов](5391101692666912993.jpg)


**Основные компоненты:**
* **Models:** `Document` (хранит строки), `TextLine` (текст + формат), `DocumentMemento` (непрозрачный снимок).
* **Patterns:** `ICommand` и его реализации (команды), `CommandManager` (Invoker), `HistoryCaretaker` (Caretaker).

## 3. Использованные паттерны и их обоснование

### Command (Команда)
Паттерн решает проблему инкапсуляции запроса в виде объекта, что позволяет параметризовать клиентов с операциями, ставить их в очередь и, главное, поддерживать отмену операций. В приложении каждая операция над документом оформлена отдельным классом (`InsertLineCommand`, `DeleteLineCommand`, `ReplaceTextCommand`, `FormatLineCommand`), реализующим интерфейс `ICommand` с методами `Execute()` и `Undo()`. Класс `CommandManager` выступает в роли Invoker: он хранит стеки выполненных и отменённых команд, ничего не зная о внутреннем устройстве документа, что позволяет легко добавлять новые типы команд без изменения существующего кода.

### Memento (Снимок)
Паттерн решает проблему сохранения внутреннего состояния объекта без нарушения инкапсуляции, чтобы впоследствии можно было восстановить это состояние. Класс `Document` (Originator) умеет создавать снимок `DocumentMemento` через метод `CreateMemento()` и восстанавливаться из него через `Restore()`. Поля `DocumentMemento` помечены как `internal`, поэтому получить доступ к содержимому снимка или изменить его извне невозможно — это гарантирует целостность истории. Класс `HistoryCaretaker` выступает хранилищем (Caretaker), сохраняя снимки по именам, не заглядывая в их внутреннюю структуру.
